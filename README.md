# Контекст — персональная бизнес-лента

Django-приложение для хакатона: регистрация, вход по email, новостная лента, профиль компании, сценарные расчёты, фильтры, поиск и сохранённые новости. Все страницы используют общий шаблон и стили.

## Запуск в PowerShell из корня проекта

```powershell
.\nvenv\Scripts\python.exe .\alphaproj\manage.py migrate
.\nvenv\Scripts\python.exe .\alphaproj\manage.py runserver
```

Откройте http://127.0.0.1:8000/ — без сессии сервис отправит на вход.

- `/register/` — регистрация: имя, email, пароль и подтверждение. После регистрации выполняется автоматический вход.
- `/login/` — вход по email и паролю. Email нормализуется в нижний регистр и используется как уникальный username стандартной модели Django User.
- `/logout/` — выход только методом POST, через кнопку в ленте.
- `/` — лента для авторизованных пользователей. Без сессии перенаправляет на `/login/?next=/`.
- `/admin/` — управление новостями для сотрудников с соответствующими правами.

Все пользовательские маршруты определены в `alphamain/urls.py`; корневой `alphaproj/urls.py` подключает их и админку. Старые адреса `/v1/…` удалены.

Пароли хешируются стандартными средствами Django, проверяются встроенными валидаторами. Формы защищены CSRF, авторизация использует серверные сессии. Пароли не хранятся в браузерном хранилище.

Для нового окружения установите Python 3.13 и зависимости: `pip install -r requirements.txt`.

## Добавление новостей

```powershell
.\nvenv\Scripts\python.exe .\alphaproj\manage.py createsuperuser
```

Войдите в `/admin/`, откройте раздел «Новости» и добавьте публикацию. По умолчанию создаётся черновик. Чтобы показать его в ленте, выберите статус «Опубликовано» и дату не позже текущей.

Модель `News` хранит заголовок, краткое содержание, полный текст, название и уникальную HTTP(S)-ссылку источника, дату публикации, категорию, тип события (риск / возможность / к сведению), статус и служебные даты. Для позиции банка предусмотрены отдельные поля текста и ссылки; текст позиции нельзя сохранить без ссылки на источник.

Если опубликованных записей нет, показываются 6 явно помеченных вымышленных демо-сценариев. После добавления записей они заменяют демо-ленту. Персональный AI-анализ для записей из базы пока не реализован — интерфейс сообщает об этом. Текст публикации и позиция банка отображаются отдельно, без выполнения HTML из материалов.

## Автоматическая загрузка новостей

В проекте есть загрузчик HTTP и парсер RSS 2.0 / Atom. Источник по умолчанию — официальная RSS-лента ТАСС: https://tass.ru/rss/v2.xml . Адреса настраиваются списком `NEWS_FEED_URLS` в `alphaproj/settings.py` или повторяющимся параметром `--url`.

Из корня проекта:

```powershell
# Проверка без записи в базу
.\nvenv\Scripts\python.exe .\alphaproj\manage.py import_news --category Экономика --limit 20 --dry-run

# Загрузка в ленту сайта
.\nvenv\Scripts\python.exe .\alphaproj\manage.py import_news --category Экономика --limit 20 --publish

# Любой другой RSS/Atom: по умолчанию новые записи станут черновиками
.\nvenv\Scripts\python.exe .\alphaproj\manage.py import_news --url https://example.com/rss --source-name "Название СМИ"
```

Параметры: `--limit` (1–500 записей на источник после фильтрации), `--category` (подстрока категории без учёта регистра), `--timeout` (1–120 секунд), `--publish`, `--dry-run`. Без `--category` загружаются все темы. Категории извлекаются из источника; все импортированные записи получают нейтральный тип, поскольку риск для конкретной компании требует отдельного анализа. Позиция банка автоматически не заполняется.

Парсер очищает HTML, сохраняет заголовок, текст, дату с часовым поясом, название источника и HTTP(S)-ссылку. Если RSS содержит только анонс, сохраняется анонс, а не выдуманный полный текст: для чтения всей статьи есть переход к первоисточнику. RSS без описания сохраняется с заголовком в качестве доступного текста.

Отсутствующие/некорректные даты, заголовки и ссылки приводят к пропуску записи с сообщением. Сбой одного источника не мешает остальным, но команда завершится с ненулевым кодом. Ограничены размер ответа (5 МБ) и время ожидания; DTD/XML-сущности запрещены.

Повторы определяются по ссылке: удаляются фрагмент и метки utm/fbclid/gclid, значимые параметры сохраняются. Редакторские правки и статусы существующих записей не перезаписываются. `--publish` публикует только новые записи; старый черновик нужно опубликовать через админку. Это не смысловое объединение перепечаток разных СМИ.

Команда выполняет один цикл и не запускается при открытии страницы. Для обновлений по расписанию в Планировщике заданий Windows создайте задание, например каждые 30 минут: программа — абсолютный путь к `nvenv\Scripts\python.exe`, аргументы — абсолютный путь к `alphaproj\manage.py` и `import_news --category Экономика --limit 20 --publish`, рабочая папка — корень проекта. Автоматическое задание не создаётся этой реализацией.

## Проверка

```powershell
.\nvenv\Scripts\python.exe .\alphaproj\manage.py check
.\nvenv\Scripts\python.exe .\alphaproj\manage.py test alphamain
.\nvenv\Scripts\python.exe .\alphaproj\manage.py makemigrations --check --dry-run
```

При доступном Node.js: `node --check alphaproj/alphamain/static/alphamain/feed.js`.

Сценарий ручной проверки: зарегистрируйтесь → измените профиль → отфильтруйте и сохраните новость → выйдите → войдите повторно → добавьте публикацию через админку → проверьте её в ленте. Проверьте, что черновики не отображаются.

## Границы текущей реализации

- RSS/Atom-парсер подключён; языковая модель ещё не подключена. Импорт PDF-аналитики банка — отдельный следующий этап. Персональные расчёты работают только для учебных сценариев; 14% — условие сценария, а не проверенная текущая ставка.
- Профиль бизнеса и избранное пока хранятся в localStorage отдельно для каждого аккаунта и режима ленты. Это не серверное хранение и не защита данных на общем компьютере; синхронизации между устройствами нет.
- ФИО в ленте и бизнес-профиле берётся из учётной записи, указанной при регистрации. Старое имя из localStorage его не подменяет; поле ФИО в бизнес-профиле доступно только для чтения.
- Регистрация не подтверждает email; сброс пароля и ограничение частоты попыток входа пока не реализованы.
- Персональный анализ нужно хранить отдельно от общей новости с привязкой к компании/пользователю и источникам. По ТЗ следующим этапом нужны контекст компании, сбор источников, ранжирование и разрешённая кейсом LLM.
- Настройки предназначены для локальной разработки; публичное развёртывание требует отдельной конфигурации.
